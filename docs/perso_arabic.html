Perso-Arabic work in legacy — script axis, done by hand

Not #define agar if. That demo is the same failure as Gurmukhi macros. The 2000s work is a script transducer plus an optional harakat layer, because Arabic-family writing is an abjad.

What is actually in the tree

FileWhat it is
urdu_map.csv (91 rows)Manual Devanagari skeleton → Nastaliq letters, with isolated / joining alternatives. ख→کھ, क→ک, virama-related forms, nukta pairs (क़→ق).
fltr_ur_hiHand-ordered sed reversing Perso-Arabic → Devanagari. Tatweel, hamza, tashkil, RTL mark. Not a mechanical inverse of the CSV.
arabic-generic.csv + fltr_ar_uniUnicode presentation forms (U+FE8D…) → canonical Arabic letters. Required before any linguistic map.
hindawi_tashkil.txtHarakat experiment: damma / kasrah / sukun on ہندوی. Vowels are optional residue on an abjad — documented, not invented away.
flatten_uni_dev.lexIndic scripts flatten to Devanagari as the hub, then the Urdu map fires.
UrduC_sample.uhinHindiC.uhin presented in Perso-Arabic (same Guru dialect, same Hindi words). Mixed leftover Devanagari is honest underspecification, not a bug to patch with heuristics in this layer.
urdu_c.tsv / persian / arabicLanguage axis: اگر→if. Separate from script.

Axes, not collapsed

script     Perso-Arabic / Nastaliq   ← urdu_map.csv, fltr_ur_hi, tashkil
language   Urdu / Persian / Arabic   ← *_c.tsv  (اگر, اگر not यदि)
standard   C after Shaili Guru       ← h2c.lex, same as HindiC.uhin

UrduC_sample.uhin is Hindi-in-Nastaliq (script). urdu_c.tsv is Urdu-the-language (keywords). Mixing them is the category error.

What the CSV does on HindiC.uhin

Longest-match on the 91-row map. Tatweel joining and hamza word-breaks in the 2004 sample are manual presentation on top of that skeleton — the JS pass does not pretend to be a Nastaliq shaper.

शैली गुरु     →  ش◌َـےلـی گـورـو     (sample uses شـےلـیء گـورـو)
पूर्णांक         →  پ◌ُـور्ݨاںک          (virama leftover)
मुख्य         →  مـوکھ्ی
वापस         →  वापस / ؤاپس         (hamza vs व — map residue)

Short-vowel residue is the abjad. Coverage report in PERSO_ARABIC.json: 42-letter BASE attested; 158 later heuristic fills are a different layer (perso2deva_heur.py) and are not this manual map.
